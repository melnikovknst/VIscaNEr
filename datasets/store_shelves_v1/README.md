# Магазинные полки: кадры и разметка для обучения

50 исходных фотографий, 253 кадра с выбранной бутылкой в центре. Разметка есть
для каждого кадра. По меткам: 139 кадров с вином из каталога,
113 — с вином вне каталога, 1 — джин Gordon's, исключён.

2026-09-27: три кадра «Abrau Collection» белое/красное (фото 21, 22) перенесены из
«вне каталога» в каталог — это «Абрау Купаж светлый/тёмный сухое» с тем же рисунком.

## Где что лежит

| Путь | Содержимое |
|---|---|
| `queries/s-001.jpg` … `queries/s-253.jpg` | Готовые кадры 3:4 для подачи модели. Целевая этикетка находится в центре; соседи и ценники могут оставаться в кадре. |
| `labels.csv` | Одна строка разметки на каждый кадр: идентификатор, файл, допустимые каталожные slugs, описание этикетки и ценника, исходное фото, статус проверки. UTF-8. |
| `source/shelf-01.jpg` … `source/shelf-50.jpg` | Исходные фотографии полок. |
| `points.csv` | Точки центров этикеток и приблизительная ширина бутылок на исходных фото, использованные для нарезки. |
| `review.json` | Замечания по шести кадрам для повторной проверки и каталожные карточки для сравнения. Эти карточки **не являются автоматически правильными ответами**. |

## Как использовать разметку

`image_path` в `labels.csv` — имя файла внутри `queries/`.
`source` — имя файла внутри `source/`.
Цель разметки — бутылка под центром кадра, а не любая из соседних бутылок.

Для отбора обучающих примеров используйте **`training_use`**:

| Значение | Кадров | Назначение |
|---|---:|---|
| `catalog` | 137 | Примеры с каталожными ответами; допустимые slugs перечислены в `accepted_slugs` через `;`. |
| `out_of_catalog` | 109 | Целевого вина нет в каталоге. Подходят для обучения отказу/распознаванию неизвестных вин; отдельные новые классы вин здесь не заданы. |
| `review` | 6 | Отложить до ручной проверки соответствия каталогу. |
| `exclude` | 1 | Джин, не использовать как размеченный пример вина. |

Несколько `accepted_slugs` означают допустимые карточки одного целевого вина,
а не несколько целевых бутылок. Не превращайте всю строку с `;` в имя одного класса.

Исходные поля сохранены: `status=ok/notcat/remove`, `in_catalog`, `scored`,
`accepted_slugs`, `note`, `source`, `x`, `y`. `scored` относится к исходной оценочной
разметке и **не учитывает повторную проверку**; для обучения ориентируйтесь на
`training_use` и `needs_review`. Это ручная разметка по видимым этикеткам и ценникам;
кроме отмеченных спорных случаев отдельной полной повторной проверки не было.

Шесть кадров для проверки:

- `s-010` — Select Blanc: на фото Chardonnay, на эталоне 0,2 л Chardonnay–Sauvignon Blanc; отличие не только в объёме.
- `s-048` — Адагум Каберне Совиньон с другой этикеткой: проверить соответствие каталожной линейке.
- `s-077` — новый дизайн сухого белого «Эндемы Шардоне»; соответствие принято по названию и типу вина.
- `s-115`, `s-172` — розовый «Портвейн Алушта»; в каталоге найдены белый и красный, исходная метка — вне каталога.
- `s-160` — «Портвейн Алушта», цвет частично перекрыт; ценник указывает красный, каталожная карточка красного существует.

## Особенности кадров

Кадры вырезаны из фотографий полок, а не сняты по отдельности. Центр соответствует
ручной точке на этикетке. При выходе за край исходника добавлен серый фон RGB
`127,127,127`: кадр не уменьшается и центр не сдвигается. Исходные перекрытия,
блики и обрезанные исходной фотографией части бутылок остаются.

Это разметка идентичности целевого вина и точек, **не готовые YOLO bounding boxes**.
В `points.csv` значения `x`, `y`, `w` заданы в процентах размеров исходного фото;
`w` — приблизительная ширина бутылки.

Кадры одного `source` сильно пересекаются: не распределяйте их случайно между
train/val/test. Повторные снимки той же полки также следует держать в одной группе.
После включения набора в обучение его нельзя использовать как независимый тест.

## Скачать и воспроизвести

Из корня репозитория:

```bash
git pull
git lfs pull --include="datasets/store_shelves_v1/**"
```

Изображения хранятся в Git LFS (около 69 МБ), CSV/JSON и этот README — обычный текст
Git. Для загрузки фотографий нужен именно `git lfs pull`, а не только указатели LFS.

Пересобрать кадры и `labels.csv` из исходников, точек и списка проверки:

```bash
python -m scripts.build_store_shelves
```

Нужен Pillow. Порядок строк `points.csv` определяет номера `s-NNN` — не меняйте его
без обновления ссылок в `review.json` и зависимых данных.
