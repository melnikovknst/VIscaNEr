# Архитектура winescanner

## Сервис

Один процесс FastAPI (`backend/main.py`) отдаёт и API, и собранный React-фронтенд
(`dist/`). Модели загружаются один раз при старте. Запросы на распознавание
выполняются последовательно под одним lock: YOLO, EasyOCR и PyTorch делят один
CUDA-контекст. Пока идёт распознавание, параллельный запрос получает `429` с
`Retry-After`.

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/v1/eval/predict` | Фото в поле `image` → `{"slug": "..." \| null}`. Эндпоинт для проверки организаторами; `/predict` — его синоним, поле `file` тоже принимается |
| `POST` | `/api/scan` | Фото в поле `file` → полная карточка: статус, вино, до 5 кандидатов с уверенностью, диагностика пайплайна |
| `GET` | `/api/health` | Готовность модели и размер каталога |
| `GET` | `/api/catalog`, `/api/catalog/{slug}`, `/api/catalog/{slug}/image` | Поиск по каталогу, карточка вина, фото бутылки |
| `POST` | `/api/pairing` | Подбор вина к блюду: через сомелье, если он включён, иначе по правилам |
| `POST` | `/api/sommelier` | Вопрос сомелье, в том числе о конкретном вине |
| `GET`/`DELETE` | `/api/history` | История сканирований посетителя (по cookie сессии) |

Полная схема — в Swagger: `http://127.0.0.1:8080/docs`.

## Пайплайн распознавания

Код: `five_stream_transformer/infer.py` (`FiveStreamInferencePipeline`) и
`joint_yolo/infer.py`.

### 1. Детекция и выбор цели

YOLO11n (`models/joint_yolo/best.pt`) за один проход находит классы `0 = bottle` и
`1 = wine_label`. Цель выбирается по `confidence + 0.20 · близость к вертикальной оси`
(гауссиана по горизонтальному расстоянию от центра кадра, σ = 0.2 ширины). Координата
Y не влияет: на полке человек наводит камеру по горизонтали, а высоту кадра выбирает
как удобно.

Этикетка вырезается с отступом 10 %, бутылка — ячейкой, в которой лежит центр
этикетки, с отступом 6 %. Если уверенность бутылки ниже 0.75, вместо вырезки
используется весь кадр. При настоящей неоднозначности (два близких кандидата)
обрабатываются оба варианта, и оценка каждого вина берётся максимальной.

### 2. Пять потоков признаков

| Поток | Источник | Размер |
|---|---|---:|
| `bottle_crop` | DINOv3-B/16 бутылки, признак до проекции | 1536 |
| `label_crop` | DINOv3-B/16 этикетки, признак до проекции | 1536 |
| `bottle_dino` | эмбеддинг поиска бутылки | 256 |
| `label_dino` | эмбеддинг поиска этикетки | 256 |
| `ocr_text` | символьные n-граммы текста EasyOCR (ru + en) | 512 |

Оба DINOv3-B лежат в одном чекпоинте Stage-2C (`models/stage2c/manual_stage2c_best.pt`,
эпоха 17): полные веса backbone, проекции и классификатора на 2 103 вина. Для
эталонов каталога все пять потоков посчитаны заранее
(`models/five_stream_transformer/gallery_features.pt`). Кеш подписан SHA-256
чекпоинта и галерей и пересобирается сам, если они изменились.

### 3. Кандидаты и Transformer

Ветки этикетки, бутылки и OCR дают по 12 ближайших вин; объединённый пул (≤ 36)
сортируется по лучшему сходству. Residual Transformer
(`models/five_stream_transformer/residual_best.pt`: 3 слоя, 8 голов, d = 256) видит
признаки запроса и всех кандидатов. К базовому логиту он добавляет ограниченную
поправку (|residual| ≤ 2.5) и тем самым исправляет ошибки отдельных веток, не
переписывая уверенные ответы с нуля.

### 4. Уверенность и отказ

`confidence` = softmax по логитам top-10 кандидатов. Это не откалиброванная
вероятность, но её шкала устойчива.

| Уверенность top-1 | `/api/scan` | `/v1/eval/predict` |
|---|---|---|
| ≥ 0.45 | `matched` — карточка вина | `slug` |
| 0.20 – 0.45 | `uncertain` — посетитель выбирает из кандидатов | `null` |
| < 0.20 | `not_found` | `null` |

Порог подобран на съёмке полок, которая не участвовала в обучении: 126 кадров с
винами из каталога и 126 — с винами вне каталога.

| Порог | Top-1, вина из каталога | `null` для вин вне каталога |
|---:|---:|---:|
| без порога | 58.7 % | 0 % |
| 0.30 | 57.1 % | 32.5 % |
| **0.45** | **54.8 %** | **51.6 %** |
| 0.65 | 46.8 % | 67.5 % |
| 0.85 | 28.6 % | 83.3 % |

Проверка на других наборах: на 130 фото полок из интернета top-1 падает с 60.0 %
до 56.9 %; на 109 кадрах вин вне каталога из другой съёмки `null` получают 45.9 %.

## Сомелье

`backend/sommelier.py`. Каждое вино каталога описано текстом из карточки и профиля
вкуса (`data/sommelier/profiles.jsonl`: сладость, тело, кислотность, ароматы,
гастрономия). Тексты проиндексированы моделью bge-m3.

1. Из вопроса читаются жёсткие фильтры: цвет, сладость, игристость. К солёным и
   мясным блюдам сладкие вина не предлагаются, если гость сам о них не просил.
2. Поиск выбирает 6 вин (не больше двух от одной винодельни).
3. Языковая модель (OpenRouter или локальная YandexGPT-5 Lite) выбирает из них
   1–3 вина и объясняет выбор со ссылками `[N]`. На странице показываются только
   вина из этого списка, поэтому вина не из каталога в ответ попасть не могут.

## Данные и обучение

- Эталоны: по одной этикетке и одному фото бутылки на каждое из 2 103 вин каталога
  (`data/inference_galleries.zip`).
- Обучение энкодеров и Transformer: синтетические кадры (этикетка каталога на фоне
  и на магазинной полке с соседями и ценниками) плюс 211 размеченных вручную
  реальных фото полок.
- Код обучения, датасеты, ноутбуки Kaggle и все промежуточные эксперименты — в ветке
  [`development`](https://github.com/melnikovknst/VIscaNEr/tree/development).
